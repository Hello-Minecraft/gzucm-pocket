# 使用教程 / 功能引导规划

> 状态：**方案待拍板**（2026-11-14 起草）
> 起因：有同学反馈「软件功能有点复杂了」。v1.3.5 加了自定义日程和考试之后，课表页顶部一排四个图标、长按空白新建、日视图、重叠轮换 —— 这些不看说明基本发现不了。

## 一、现状盘点

| 已有 | 位置 | 谁能看到 | 问题 |
|---|---|---|---|
| README「功能」一节 | GitHub 仓库 | 会点进仓库的人 | 偏开发者视角，没有步骤 |
| `使用说明.md` | 桌面发包目录 + Release 附件 | 下载 APK 的人 | 一次性资料，装完就找不到了 |
| `ReleaseNotes.kt` | App 内「关于 → 更新日志」 | 所有人 | 只写「这版改了什么」，不教怎么用 |
| — | App 内 | — | **没有任何帮助入口** |

结论：不缺「写过的字」，缺的是**在 App 里、按操作顺序、随时能查到**的那份。

## 二、目标（可验收）

1. 新用户不看人问，3 分钟内走完：登录 → 看到本周课表 → 加一条自己的日程。
2. 已知功能的用户遇到具体问题（「怎么让提醒准一点」「重叠的课怎么看另一门」），30 秒内在 App 里查到。
3. 教程跟版本同步：发版检查单里加一条「这版改动涉及到的教程段落过一遍」。

## 三、形态方案对比

| 方案 | 长什么样 | 优点 | 代价 / 风险 | 推荐度 |
|---|---|---|---|---|
| **A. App 内置「使用帮助」面板** | 设置页多一行「使用帮助」，进去是一屏目录 + 分节展开的图文 | 随时可查、离线、跟版本同包、不用装第二个 App | 要写文案（1 天）+ 一个纯静态面板（半天）；以后每版都要顺一遍 | **推荐，做主入口** |
| B. 首次登录后的分步引导 | 半透明遮罩 + 气泡，一步步高亮周条 / 日视图 / 日程图标 / 长按空白 | 新用户一定看得到 | 容易烦；要存「已看过」状态；换设备/重装会重来；改版就要重做引导 | 只做**一条**轻提示，不做全流程 |
| C. 外部文档（GitHub Pages / 腾讯文档） | App 里放个链接，跳浏览器 | 改起来最快，图文随便排 | 要联网、要跳出 App、链接可能挂 | 作为兜底：README 里放链接 |
| D. 视频 / GIF | B 站或网盘 | 传播力最好，适合发群 | 录制剪辑成本高，改一个界面就得重录 | 暂不做 |

**建议组合：A（主）+ C（兜底）+ B 只做一条 3 秒气泡。** 理由：A 解决「随时查」，C 解决「转给同学看」，B 只解决「知道有这个功能」，做多了都是负担。

## 四、内容结构

按**任务**分节，不按页面分。每节固定三件套：一句话说明 → 3~5 步操作 → 一个「容易踩的坑」。

| # | 节 | 要点（写的时候按这个展开） |
|---|---|---|
| 1 | 第一次用 | 本科 / 研究生两套登录入口；同步在拉什么；学段怎么切；登录失败最常见的两种（密码错、教务维护） |
| 2 | 看课表 | 周视图 ↔ 日视图；左右滑翻周、周条跳周、「回到本周」；课名 / 教师 / 教室分别在哪看 |
| 3 | 认清课表上的块 | 实线 = 教务课，虚线 = 自建日程，红色虚线 = 考试；时间重叠时右下角 ⇄ 轮换 |
| 4 | 加一条日程 | 三个入口（顶部图标、长按空白格、日视图「加个日程」）；按节次 / 按时间两种填法；每周重复；颜色；和课程撞了会怎么显示 |
| 5 | 考试 | 教务排考后自动同步；点开看考场、座位、监考；和日程撞时段时能互相切换 |
| 6 | 成绩 | 课程 / 等级 / 体测三类；研究生只有一部分 |
| 7 | 电费 | 数据来源（一卡通）；每天首次打开自动更新；低电量提醒；一卡通要单独登录 |
| 8 | 提醒为什么不准 | 厂商后台限制（小米 / OPPO / 华为各写一句）；增强提醒是什么、什么时候开 |
| 9 | 常见问题 | 同步失败怎么办；周次和教务差一周（口径：教务第 N 周 = 周日~周六）；换设备数据怎么带；卸载会丢什么（只丢本地日程和设置） |

第 3 节单独拎出来，是因为「虚线 vs 实线 vs 红色」是这套界面里唯一需要先解释的视觉约定，不讲的话用户分不清哪块是自己加的。

## 五、落地步骤

| 步 | 做什么 | 产出 | 估时 |
|---|---|---|---|
| 1 | 写文字稿，按上面 9 节 | `docs/使用教程.md`（可先只在仓库里） | 我写，0.5 天 |
| 2 | 配图 | 复用 `docs/screenshots/` 四张，补拍日程、考试详情、日视图三张 | 我拍，0.5 小时 |
| 3 | 桌面 `使用说明.md` 改成「教程的精简版」 | 发包通道那份 | 0.5 小时 |
| 4 | App 内面板 | 设置页加「使用帮助」→ 一个 `HelpSheet`，目录 + 分节，纯 Compose 静态内容，不引第三方 | 0.5~1 天 |
| 5 | 首次提示（可选） | 第一次进课表时，日程图标旁一个 3 秒气泡「这里能加自己的日程」 | 0.5 天 |
| 6 | 发版检查单 | 加一条「涉及改动的教程段落过一遍」 | 10 分钟 |

步骤 1、3 不涉及代码，可以马上做；4 要改代码，得跟着某次发版走。

## 六、需要拍板的四件事

1. **教程放哪**：只发文档 / 也内置到 App？（我推荐内置，一屏目录，不用跳浏览器）
2. **要不要首次引导**：全流程 coach marks / 只一条气泡 / 完全不要？（我推荐只一条气泡）
3. **写给谁**：只写本校同学（含研究生）能看懂，还是外部用户也能照做？
4. **要不要视频**：我倾向先不做，教程稳定一两个版本后再说。

## 七、风险

- **写了没人看**：入口位置比内容更重要。设置页那行 + 首次气泡 + 「关于」页底部各放一个入口，比写得多漂亮都有用。
- **维护成本**：只写「不会变」的操作流程，具体交互细节交给更新日志；截图宁少勿多，界面一改就得重拍。
- **和 `使用说明.md` 分叉**：两份文案要么同源（从教程里摘），要么明确分工 —— 桌面那份只写「装哪个包、怎么装、数据在哪」。
