# 广中医教务接口对接规格

> 2026-10-28 实测确认，用真实会话拉取 202601 学期数据验证。
> 用于把 ZZUPocket（郑大版）改造为广中医版。**接口随时可能被学校调整，失效后按此文档重新抓包。**

## 1. 系统架构

| 层 | 地址 | 协议 |
|---|---|---|
| 统一身份认证 | `authserver.gzucm.edu.cn/authserver/login?service=…` | 金智 Wisedu CAS（`/authserver/login` 是金智标准路径） |
| 教务系统 | `jw.gzucm.edu.cn` | Tomcat 7，`/new/*` 路径，layui 前端，会话靠 `JSESSIONID` |
| CAS 入口 | `GET /new/ssoLogin` | 302 跳 authserver，登录后带 ticket 回跳 |

**广中医和郑大走的是两套完全不同的认证模型**：郑大用树维 Supwisdom 的 token API（RSA 加密账密 + 短信 MFA → idToken，有效期约 1 个月）；广中医是传统 CAS + 服务端会话 Cookie。ZZUPocket 的 `CasClient.kt` 在此完全不可用。

## 2. 登录

### 2.1 表单直登（有验证码，不建议自动化）

```
POST /new/login
Content-Type: application/x-www-form-urlencoded
account=学号&pwd=密码&captchaToken=<天爱验证码令牌>&clientId=<会话标识>
```

- 验证码：`GET /new/captcha`，实测为**天爱（tac.min.js）滑动/旋转码**，命令行无法自动通过。
- 成功判定：页面跳转到 `/new/welcome.page?ui=new`，同时落下 `JSESSIONID`。

### 2.2 推荐做法（App 内 WebView）

WebView 打开 `https://jw.gzucm.edu.cn/` → 用户自己输账密、滑验证码 → 从 `CookieManager` 取回 `JSESSIONID` → 注入 OkHttp 的 `CookieJar`。

ZZUPocket 里已有现成实现可抄：`data/gms/GmsCookie.kt` + `GmsScheduleSource.onWebViewLogin()`，那套就是"只取 Cookie、不碰密码"的模式。

### 2.3 会话寿命

`JSESSIONID` 是 Tomcat 会话，**比郑大的 1 个月 JWT 短得多**。必须做：
- 启动时静默探活（发一次轻量请求，`code=-401` 即失效）
- 失效直接回登录页，不做无限重试

## 3. 课表主接口

```
POST /new/student/xsgrkb/getCalendarWeekDatas
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: https://jw.gzucm.edu.cn/new/student/xsgrkb/main.page

xnxqdm=202601&zc=&d1=2026-07-26 00:00:00&d2=2027-02-28 00:00:00
```

| 参数 | 含义 | 备注 |
|---|---|---|
| `xnxqdm` | 学期代码 | `YYYY01`（秋）/ `YYYY02`（春） |
| `zc` | 周次过滤 | 留空 = 全部 |
| `d1` / `d2` | 日期区间 | 给宽区间一次拿全，实测 7 个月跨度正常返回 |

返回 `{"code":0,"message":…,"data":[…]}`，未登录时 `{"code":-401,"message":"尚未登录，请先登录"}`。

**一次请求拿整学期，之后切周纯本地计算** —— 这点和郑大的 EAMS 一致，ZZUPocket 的仓库设计可以照搬。

## 4. 字段映射（→ ZZUPocket `domain/Session`）

实测 202601 学期返回 50 条排课任务、40 个字段，展开为 233 个「周 × 课」单元。

| 广中医字段 | 含义 | 映射到 | 处理要点 |
|---|---|---|---|
| `kcmc` | 课程名 | `courseName` | 直接 |
| `kcdm` | 课程代码 | `courseCode` | 直接 |
| `teaxms` | 教师姓名 | `teacher` | 逗号分隔，常多达 10+ 人（合班授课） |
| `xq` | 星期 | `weekday` | int 1–7，实测全覆盖 |
| `ps` / `pe` | 起始/结束节次 | `startUnit` / `endUnit` | **字符串，带前导 0**（`"01"`/`"02"`），要 `lstrip("0")` |
| `qssj` / `jssj` | 起止时间 | `startTime` / `endTime` | `HH:mm:ss`，直接可用 |
| `jxcdmc` | 主教室名 | `roomText` | 86% 非空 |
| `jxcdmc2` | 逐周教室 | 逐周 `roomText` | 见 §5，**核心字段** |
| `zc` | 周次串 | 备用周次 | 无序逗号分隔（`"1,14,2,8,18,…"`） |
| `jxhjmc` | 教学环节 | 课程类型 | 理论教学 / 实验教学 / **实习见习** |
| `jxmsmc` | 教学模式 | 可选标签 | PBL / 线上线下教学 / 线上教学 |
| `jxbmc` | 教学班 | 可选 | 如「一院23中医(铁涛)5」 |

**没有 `date`（具体日期）字段**，需要客户端自己算：`学期第一周周一 + (week-1)×7 + (weekday-1)`。

## 5. 关键坑：`jxcdmc2` 的两种形态

这是整个对接里最容易踩的地方。`jxcdmc2` 是逗号分隔的「教室-周次」串：

```
综教楼804（智慧课室）-8,综教楼804（智慧课室）-9,综教楼804（智慧课室）-4
```

但也存在**教室名为空、只剩周次**的情况：

```
-12,-13
```

原因是该周次没排具体教室。解析时必须回退到 `jxcdmc`：

```python
for tok in (jxcdmc2 or "").split(","):
    m = re.match(r"^(.*)-(\d{1,2})$", tok.strip())
    if m:
        week = int(m.group(2))
        room = m.group(1).strip() or jxcdmc   # ← 空名回退主教室
```

若 `jxcdmc2` 为空，退回 `zc` 拆周次 + `jxcdmc`。

**见习轮转**是最典型的用例：同一门课同一时段，`jxcdmc2` 里挂着十几个不同科室，各对应不同周：

```
一附院泌尿外科-14,一附院肛肠科-12,一附院甲状腺疝外科-10,…(共8个)
```

所以数据模型必须支持「同课程 + 同时段 + 不同周 → 不同教室」。ZZUPocket 的 `Session` 是每条带 `weekIndex` 的扁平记录，天然支持。

## 6. 作息时间（实测）

每节 45 分钟、节间 5 分钟，**节次编号有跳号**（不存在 5、10、11）：

| 节次 | 开始 | 节次 | 开始 |
|---|---|---|---|
| 1 | 08:30 | 7 | 14:50 |
| 2 | 09:20 | 8 | 15:40 |
| 3 | 10:20 | 9 | 16:30 |
| 4 | 11:10 | 12 | 19:00 |
| 6 | 14:00 | 13 | 19:50 |

渲染时按接口返回的 `ps` 原样排行，不要按 1..N 连续铺满——会出现整行空白。

## 7. 数据质量实测

| 项 | 结果 |
|---|---|
| 缺星期 | 0 / 233 |
| 缺节次 | 0 / 233 |
| 缺周次 | 0 / 233 |
| 缺教室 | 22 / 233（9.4%，含回退 `jxcdmc` 后仍空） |
| 课程类型 | 理论 184 / 实验 47 / 实习见习 2 |
| 周次覆盖 | 1–19 周 |

缺教室的条目是「待定」状态（多为 9 节单独加课、周六实践课），UI 上要能显示占位而不是空白。

## 9. 待定项：学期第一周周一

接口不给，必须外部提供。当前取值 **2026-09-07**（用户确认）。

稳妥做法：
1. 做成可配置项，每学期改一次；
2. 或显示「现在是第几周」让用户校准偏差；
3. 或从教务部校历页面抓（多一个请求，且格式随年份变）。

对渲染影响有限——只要「当前第几周」正确，课表就正确；绝对日期只影响「今天」视图的日期显示。
