# 广中医生活服务接口规格（一卡通 / 订水）

> 2026-10-28 凌晨实测。抓包方式：mitmproxy + PC 微信（小程序走系统代理，证书只需装到当前用户根存储）。
> 文中所有凭据（手机号、学号、unionid、token）一律不落文档。

---

## 一、校园一卡通（ecard.gzucm.edu.cn）

### 1.1 与教务共用一套 CAS

```
GET  /user/login
  → 302 /sso//login?t=12&redirectUrl=…
  → 302 https://authserver.gzucm.edu.cn/authserver/login
        ?service=https://ecard.gzucm.edu.cn/sso/login?CLIENT_IP=…&plat=gzzyy&t=12
  → 登录后回跳，落 JSESSIONID（Path=/user 与 /sso 各一份）
```

**关键**：`plat=gzzyy` 是平台标识；认证中心就是教务用的那个 `authserver.gzucm.edu.cn`。所以**只要教务那边 CAS 会话还在，一卡通可以免密进入**——实测在已登录教务的浏览器里直接跳转，零输入登入。

移植时的意义：App 里一次 CAS 登录，可以同时拿教务和一卡通的会话。

### 1.2 入口与接口

主界面：`GET /user/index`（服务端渲染，余额直接写在 HTML 里）
功能入口：`POST /user/api/serviceHall/getInfo` `codeStr=<编码>`，返回 `funcCode` + `url`

实测功能清单：

| 功能 | funcCode | URL |
|---|---|---|
| 钱包充值 | — | — |
| 代人充值 / 消费账单 / 钱包安全 / IC卡管理 | — | — |
| **电费充值** | `YC0Xbdo3jJ` | `/user/powerfee/index` |
| **电费退款** | `q4lAo2J1K8` | `/user/feeRefund/toRefund?feeType=PowerFee` |
| 三元里6栋网费充值/退费 | — | — |
| 体育场馆预约 | — | — |

### 1.3 电费接口（核心）

```http
POST /user/powerfee/getBalance
Content-Type: application/x-www-form-urlencoded

implType=CGCOMMON1001&schoolAreaNo=2&buildingNo=5754&roomNum=5770&from=&token=<页面下发的 token>
```

返回：

```json
{"ret":true,"msg":"查询成功",
 "obj":{"roomNum":"5770","schoolAreaNo":"2","buildingNo":"5754",
        "powerBalance":"11.78","du":"度",
        "waterBalance":null,"hotWaterBalance":null, …}}
```

要点：
- **房间号是账号绑定的**，页面已带出 `schoolAreaNo/buildingNo/roomNum`，不需要用户每次选楼栋（比郑大那套维护 59 栋楼房间表省事得多）。
- `token` 是页面渲染时下发的会话 token（形如 `node01…`），不是 JWT，随页面生命周期走。
- 支付方式：`POST /user/commonfee/getPayWay`（只读，返回可用支付渠道）。

### 1.4 用电明细

页面文案（`/user/powerfee/index` 点「用电明细」后）直接给出**逐日历史**：

```
月度：2026-10  日用电 2.88  剩余 74.04  总用电 28.62
10-01  日用电 0.18  剩余 73.86  总用电 28.80
10-02  日用电 1.08  剩余 72.78  总用电 29.88
10-03  日用电 1.78  剩余 71.00  总用电 31.66
10-04  日用电 1.79  剩余 69.21  总用电 33.45
```

- 这是一条**连续递减的逐日序列**，`getBalance` 返回的当期值就是序列末值。
- `POST /user/powerfee/showDailyDetails` 只回 `true`，明细数据由页面内嵌渲染，接口层还没单独定位到。
- **移植价值**：学校直接下发历史，不用像郑大那样靠 WorkManager 定时采样攒曲线。趋势图、日均用电、预计可用天数都能直接算。

### 1.5 其他观测

- `GET /msg/ws/ws` 是一条 WebSocket 长连接（消息推送），网页开着就会挂着，移植时可以不要。
- 小程序侧入口带 `openid` + `sno`（`POST /user//demo/health/db`），说明小程序用 openid 绑定；网页侧走 Cookie + 页面 token。

## 二、订水（DD订水 / 盛泽科技 SaaS）

### 2.1 基本信息

| 项 | 值 |
|---|---|
| 小程序 appid | `wx31534ce9348737da` |
| 后端 | `ddds.shengzekeji.cn` |
| 静态资源 | `dingshui.oss.shengzekeji.cn/public/static/miniImages/{unionid}/…` |
| 前端框架 | uni-app（有 `tongji-collector.dcloud.net.cn` 埋点） |
| 系统名 | DD订水（`ddds` = DD订水） |
| 与学校关系 | **第三方 SaaS**，和教务/一卡通完全无关 |

### 2.2 两条认证通道（关键）

**通道 A：微信登录（小程序内）**

```http
POST /wx/authLogin
{"unionid":"<unionid>","code":"<wx.login() 返回的 code>","from":"WECHAT_MINI"}
→ {"code":10000,"data":{"token":"<JWT>"}}
```

- `code` 只能用微信客户端产生，一次性、短时效。
- JWT：HS256，`iss=dingshui`，**有效期 14 天**（实测 iat→exp 正好 14 天）。
- 后续请求头：`Authorization: Bearer <JWT>`。

**通道 B：手机号 + 密码（接口存在，但产物不可用）**

```http
POST /wx/login
{"phone":"<手机号>","password":"<密码>"}
```

- 参数名实测确认是 `phone` / `password`（用其它字段名会报「帐号和密码不能为空」，用 `phone` 才进入密码校验）。
- 用户信息里有 `last_edit_password_time` 字段，说明 DD订水 有独立的密码体系。
- ⚠️ **但这条通道拿到的 token 调不了业务接口，实测见 §2.6，不要在这上面浪费时间。**

### 2.3 接口清单（均 GET，带 Bearer）

| 接口 | 用途 | 备注 |
|---|---|---|
| `GET /wx/userCenter` | 用户中心 | 含 region 三级 ID、address、nickname、phone、session_key |
| `GET /wx/getUserInfo` | 用户信息 | 同上，另有 `last_edit_password_time` |
| `GET /wx/orderList` | 订单列表 | 返回 `total/missed/delivered/finished` |
| `GET /wx/addOrder` | 下单页配置 | 含 `productList`（商品/水价）、配送方式、服务费 |
| `GET /wx/homeSupplierTips` | 校区供应商 | 返回 `三元里校区` 等 |
| `GET /wx/getWelfareSetting` | 福利/优惠设置 | |
| `GET /wx/getDiscountCouponSetting` | 优惠券开关 | |
| `GET /wx/getBackBucketShowStatus` | 空桶回收状态 | |
| `GET /wx/getEnterpriseWeChatManage` | 企微群二维码 | 「DD订水｜广中医福利群」 |
| `GET /wx/getTemplateIds` | 订阅消息模板 | |
| `GET /wx/getHomePopUp` | 首页弹窗 | |
| `GET /wx/getThemeSetting` | 主题配置 | |
| `POST /wx/recordLaunchCount` | 启动计数 | |

### 2.4 路由特性（坑）

同一个 `/wx/` 前缀下，**method 参与了路由注册**：

- GET 接口用 POST 调 → `{"code":40001,"msg":"module not exists:wx"}`
- POST 接口用 GET 调 → 同样报 module not exists

这个报错信息极具误导性（看起来像路径不存在），实际是 **method 不匹配**。调试时先对齐 method，不要被文案带偏。

### 2.5 token 复用的实测结论

把抓到的 JWT 拿出来重放（完整复刻 UA / referer / xweb_xhr / 全部请求头，直连与经代理两条路径都试过）：

```
{"code":40302,"msg":"授权标识已拒绝"}
```

- 不是 IP 问题（代理与直连结果一致）。
- 不是 UA 问题（原样复刻全部头仍拒）。
- 不是 token 刷新问题（整个会话只发生过一次 `authLogin`，只有一个 token）。

推断：服务端对该 JWT 做了会话级绑定（可能关联 `session_key` 或 jti 白名单），**不支持跨端重放**。

### 2.6 密码登录通道的实测结论（02:00 更正，此前的乐观判断作废）

用真实手机号 + 密码调 `POST /wx/login`，**登录本身是成功的**：返回 200 字符合法 JWT，签名结构完整，`client_type` 仍为 `wechat_mini`。但拿这个 token 调任何业务接口一律被拒：

```
GET /wx/userCenter  → {"code":40302,"msg":"授权标识已拒绝"}
GET /wx/orderList   → {"code":40302,"msg":"授权标识已拒绝"}
GET /wx/getUserInfo → {"code":40302,"msg":"授权标识已拒绝"}
```

已排除的可能：

| 假设 | 验证结果 |
|---|---|
| header 名不对 | 改 `token` / `X-Token` / `Access-Token` 都退回 `40300 授权标识为空`，说明服务端就是只认 `Authorization` |
| 缺 Bearer 前缀 | 裸 token 同样 40302 |
| IP 出口不同 | 经 mitmproxy 转发与直连结果一致 |
| UA / referer 不对 | 原样复刻抓包的全部请求头仍 40302 |
| token 被刷新吊销 | 整个会话只发生过一次 authLogin |
| 有 H5/PC 端可走 | `/`、`/h5/`、`/web/`、`/pc/`、`/index.html`、`/api/` 全部 404 |

**根因**：微信登录链路里有一道 `POST /wechat/wechat_user/miniOauth2`，body 是 `{unionid, token}`，用于把「微信身份 ↔ DD订水账号」的会话映射建立起来。密码登录**跳过了这一步**，后端没有对应的会话记录，于是 token 虽然签名合法，查不到绑定的用户 → 拒绝。而 `unionid` 只有微信客户端能给。

**最终结论：DD订水 无法移植到第三方 App，只能在微信小程序内使用。订水功能放弃。**

## 三、抓包方法（可复现）

```bash
# 1. 起代理
mitmdump -p 8080 -s tap.py --set connection_strategy=lazy

# 2. 证书装到当前用户根存储（不需要管理员）
certutil -user -addstore Root "$USERPROFILE\.mitmproxy\mitmproxy-ca-cert.cer"

# 3. 系统代理指向 8080（HKCU，用户级）
#    ProxyEnable=1, ProxyServer=127.0.0.1:8080
# 4. PC 微信打开小程序操作
# 5. 收工还原 ProxyEnable=0
```

要点：
- **PC 微信的小程序流量走系统代理，且信任当前用户根存储的 CA**（实测通过，`/user//demo/health/db` 那条心跳就是小程序发的）。
- 小程序包本身是 `V1MMWX` 加密格式（微信 4.0 新格式），解包成本高，抓包更划算。
- 微信数据目录：`D:\70667\AppData\Tencent\xwechat\radium\users\<hash>\applet\packages\wx<appid>\<ver>\`。

## 四、移植结论

| 模块 | 可行性 | 路径 |
|---|---|---|
| 一卡通余额 / 电费查询 | ✅ 完整可移植 | CAS 复用 + `powerfee/getBalance` |
| 用电趋势 | ✅ | 页面内嵌明细（接口层待补） |
| 体育场馆预约 | ⚠️ 待探 | 一卡通内有入口 |
| 订水（查订单/下单页/水价） | ✅ 可移植 | `/wx/login` 手机号密码 |
| 订水支付 / 一卡通充值 | ❌ 不做 | 涉及资金，一律不做自动化 |

**整体架构影响**：ZZUPocket 删掉的 `data/ecard/` 那一层，在广中医版本里要**重新写一份**——但数据源换成 `ecard.gzucm.edu.cn`（CAS + 页面 token），而不是郑大的一卡通 API。原先准备"整块删掉"的判断需要修正：电费这块广中医是有的，而且数据比郑大更全。
